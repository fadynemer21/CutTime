# Store screenshot plan

Capture only real, coherent test data. Do not show personal email addresses,
real FCM tokens, Firebase console secrets, debug banners, development fallback
shops, permission errors, or placeholder owner information.

## Recommended phone screenshots

1. **Find your barber** — customer Home with two complete real shops and a
   useful search result.
2. **Shop details** — public profile showing description, rating, hours,
   services, and clean gallery images.
3. **Choose a time** — booking form with a service, date, and available time
   selected, before the review step.
4. **Review with confidence** — booking review summary with no customer PII.
5. **Manage appointments** — customer appointment list with a realistic
   upcoming and completed entry.
6. **Run your shop** — Barber Dashboard with today's schedule and customer
   names.
7. **Control availability** — working hours and a holiday entry.
8. **Stay on time** — notification settings or inbox emphasizing two-hour and
   30-minute reminders.

## Optional tablet screenshots

- two or more barber cards with comfortable expanded-width spacing;
- Barber Dashboard with multiple appointment sections;
- profile/gallery layout.

## Capture rules

- Use the release candidate theme and icon.
- Set device time/date so appointments are clearly future or completed.
- Use fictional names and shops.
- Keep status bar clean and battery above 50%.
- Capture at native device resolution; do not stretch screenshots.
- Verify text is not clipped at default font scale.
- Avoid red error states unless a feature explanation explicitly needs one.
- Maintain a consistent fictional data set across all frames.
- Review current Play Console image dimension/count requirements at submission
  time.

## Asset tracking

For every final image record:

- filename;
- device/API/profile;
- app version code/name;
- locale and font scale;
- source account/data seed;
- whether personal data review passed;
- whether the image was uploaded to Play Console.
